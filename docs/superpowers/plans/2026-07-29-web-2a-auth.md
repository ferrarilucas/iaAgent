# apps/web — Plano 2a (Scaffolding + Auth) — Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffolding do `apps/web` (Next.js App Router + Tailwind) com login por OTP no WhatsApp via Better Auth, usando a nossa tabela `users` única (estendida) e entregando o código pelo `packages/whatsapp`.

**Architecture:** Next.js server-side consumindo `packages/db` direto. Better Auth com adapter Drizzle sobre o `packages/db`; o plugin phone-number entrega o OTP via `packages/whatsapp` (`sendText`). O schema do Better Auth (colunas extras no `users` + tabelas `session`/`account`/`verification`) é **gerado pela CLI do Better Auth** e reconciliado no `packages/db`, para não chutar o schema.

**Tech Stack:** Node 20+, pnpm, TypeScript strict, Next.js (App Router), Tailwind, Better Auth (`better-auth`) + adapter Drizzle, `@ia/db`, `@ia/whatsapp`, Vitest.

## Global Constraints

- **NUNCA adicionar comentários no código** — nenhum `.ts`/`.tsx`/config.
- **TypeScript strict.**
- **Uma tabela de usuário só:** o Better Auth usa a nossa `users` (estendida), não uma paralela. As tabelas `session`/`account`/`verification` do Better Auth são encanamento de auth (permitidas).
- **Segredos só via env:** `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `EVOLUTION_API_URL`, `EVOLUTION_INSTANCE`, `EVOLUTION_API_KEY`. Validar na inicialização.
- **OTP entregue via `packages/whatsapp`** (`sendText`), nunca SMS/Evolution direto duplicado.
- **`bootstrapUser` do agente deve continuar compatível** após estender `users` (os campos novos têm default/nullable). Rodar `pnpm --filter @ia/db test` verde ao fim da Task 2.
- **Reconciliação de schema/versão:** a API/schema exatos do Better Auth vêm da doc/CLI da versão instalada; ao divergir do código deste plano, ajuste para a API real mantendo o comportamento (OTP por WhatsApp, sessão por cookie, uma tabela users). Registrar ajustes no report.

- [ ] **Step 1: `apps/web/src/app/login/page.tsx` (client component)**

```tsx
"use client";
import { useState } from "react";
import { useRouter } from "next/navigation";
import { authClient } from "@/lib/auth-client";

export default function LoginPage() {
  const router = useRouter();
  const [numero, setNumero] = useState("");
  const [codigo, setCodigo] = useState("");
  const [etapa, setEtapa] = useState<"numero" | "codigo">("numero");
  const [erro, setErro] = useState("");

  async function pedirCodigo() {
    setErro("");
    const { error } = await authClient.phoneNumber.sendOtp({ phoneNumber: numero });
    if (error) { setErro("Nao consegui enviar o codigo. Confere o numero."); return; }
    setEtapa("codigo");
  }

  async function verificar() {
    setErro("");
    const { error } = await authClient.phoneNumber.verify({ phoneNumber: numero, code: codigo });
    if (error) { setErro("Codigo invalido."); return; }
    router.push("/app");
  }

  return (
    <main className="mx-auto flex min-h-screen max-w-sm flex-col justify-center gap-4 p-6">
      <h1 className="text-2xl font-bold">Entrar no painel</h1>
      {etapa === "numero" ? (
        <>
          <input className="rounded border p-3" placeholder="Seu numero (ex: 5511999999999)" value={numero} onChange={(e) => setNumero(e.target.value)} />
          <button className="rounded bg-black p-3 text-white" onClick={pedirCodigo}>Enviar codigo no WhatsApp</button>
        </>
      ) : (
        <>
          <input className="rounded border p-3" placeholder="Codigo de 6 digitos" value={codigo} onChange={(e) => setCodigo(e.target.value)} />
          <button className="rounded bg-black p-3 text-white" onClick={verificar}>Entrar</button>
        </>
      )}
      {erro ? <p className="text-red-600">{erro}</p> : null}
    </main>
  );
}
```

- [ ] **Step 2: `apps/web/src/app/(app)/layout.tsx` (server, protege a area)**
